How Flair works

Progressive. Use @extend to bring as much or as little of Flair into your application as you need. The library’s Sass placeholders only produce CSS when extended, so unused placeholders stay out of your compiled stylesheet.

Declarative. Choose and compose styles in your Sass source, which compiles to CSS before reaching the browser. Your HTML can stay minimal and semantic, with the same markup styled differently by different stylesheets.

SCSS. Named placeholder selectors can extend one another, building from individual visual treatments to patterns, components and whole page layouts. Add your own design decisions at each level, layering your project’s identity over a shared base.

Directory structure

Stylesheet hierarchy

Flair organises styles by responsibility and composition, from shared values to individual pages. These categories describe what a rule owns, increasing in specificity through each layer.

  1. Variable

    Shared values and configurable design decisions: palettes, semantic colours, spacing, typography scales, borders, motion and breakpoints.

    variable/ · Public CSS properties: --pal-*, --size-*

  2. Decoration

    A visual treatment that can be applied to different kinds of UI, such as body typography, an elevated surface, muted text or a focus ring. It does not define a complete control or content structure.

    decoration/ · %d-*

  3. Element

    Default presentation for native HTML elements, including normalisation: the body, headings, links, buttons, inputs and tables.

    element/ · HTML selectors

  4. Object

    One recognisable UI unit, independent of a particular application. A button, badge, form field, avatar or progress indicator is an object; it may contain several HTML elements.

    object/ · %o-*

  5. Pattern

    A repeatable relationship between UI units, including their arrangement and presentation of state: form fields, an action group, a navigation list or repeated editable rows.

    pattern/ · %p-*

  6. Layout

    The spatial arrangement of major regions or collections: a sidebar beside content, a split pane, a responsive gallery grid or a dashboard grid.

    layout/ · %l-*

  7. Component

    Styles attached to a named HTML component, composing the lower layers and defining its particular presentation: contact-form, request-editor, site-nav or pricing-card.

    component/ · Custom-tag selectors

  8. Page

    Composition and exceptions specific to a route or page template, such as a homepage hero arrangement, documentation page or account settings page.

    page/ · Page-scoped selectors

Layer boundaries

Visual treatments. Decorations define reusable appearance, such as a surface background, border and shadow. A card that combines this treatment with a heading, content and actions is an object. Spacing belongs to the object or pattern that needs it and uses shared variables; individual padding and margin values do not need their own placeholders.

HTML defaults and shared UI styles. Element styles apply defaults to native HTML tags. Objects define styles for a UI role that may be used by different tags. Both a native button and a download link can extend %o-button, while retaining their own HTML semantics.

button {
	@extend %o-button;
}

.download-link {
	@extend %o-button;
}

The button rule belongs in Element; the reusable definition belongs in Object. The numbered hierarchy is therefore not a strict Sass dependency order. Element can consume Object, and module dependencies should be explicit.

Grouping and positioning. Patterns arrange related UI units, such as fields within a form. Layouts position larger regions or collections, such as a sidebar beside the main content. Objects, patterns and layouts can all require a particular HTML structure.

  • Form fields are a pattern; a sidebar beside main content is a layout.
  • A photo grid is a layout; its image tiles are objects.
  • Blog comments are a pattern; a particular <blog-comments> implementation is a component.
  • A calendar composes objects and patterns, potentially as a component; its month grid is a layout.

HTML components. Component styles belong to a named HTML component, which can be reused within one application or across projects. Flair provides generic components; applications define specialised ones. A <contact-form> can use %p-form-fields, with submission handling owned by the application.

Where does a rule belong?

  1. A configurable value? Variable.
  2. A visual treatment? Decoration.
  3. A default for a native tag? Element.
  4. One UI unit? Object.
  5. Related UI units organised together? Pattern.
  6. Major regions or collections arranged spatially? Layout.
  7. Presentation owned by a named HTML component? Component.
  8. Something specific to a page or template? Page.

Extending Flair

Applications follow these categories where useful, extending Flair’s definitions and supplying their own theme values and component styles. Empty directories are unnecessary. Flair owns design and layout; application data, business rules and submission handling stay with the implementing project.

Placeholder-based styles produce CSS when extended. Concrete element defaults and other directly emitted rules produce CSS when their modules are included, so those entry points should be opt-in. Sass does not automatically remove unused concrete selectors.
