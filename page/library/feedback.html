Flair library / 08

Feedback

Notices, validation summaries, status labels, progress and empty states.

Notices

Each message names its meaning in text. Static examples do not use alert roles or announce themselves on page load.

Information

This is a preview environment.

Success

The example configuration is valid.

Warning

The example storage allocation is nearly full.

Error

The example request could not be completed. Try again later.

HTML and Sass 
<div class="demo-stack">
	<aside class="demo-notice">
		<strong>Information</strong>
		<p>This is a preview environment.</p>
	</aside>
	<aside class="demo-success">
		<strong>Success</strong>
		<p>The example configuration is valid.</p>
	</aside>
	<aside class="demo-warning">
		<strong>Warning</strong>
		<p>The example storage allocation is nearly full.</p>
	</aside>
	<aside class="demo-danger">
		<strong>Error</strong>
		<p>The example request could not be completed. Try again later.</p>
	</aside>
</div>
@use "flair";

.demo-stack {
	@extend %p-stack;
}

.demo-notice {
	@extend %o-notice;
}

.demo-success {
	@extend %o-notice-success;
}

.demo-warning {
	@extend %o-notice-warning;
}

.demo-danger {
	@extend %o-notice-danger;
}

Validation summary

A summary links to the controls needing attention. Validation and submission logic remain application responsibilities.

Two fields need attention

  • Enter your name
  • Enter a valid email address
HTML and Sass 
<div class="demo-stack">
	<div class="demo-danger demo-prose">
		<h3>Two fields need attention</h3>
		<ul>
			<li><a href="#feedback-name">Enter your name</a></li>
			<li><a href="#feedback-email">Enter a valid email address</a></li>
		</ul>
	</div>
	<label class="demo-field"
		><span>Name</span
		><input
			id="feedback-name"
			aria-invalid="true"
			aria-describedby="feedback-name-error"
			autocomplete="name"
		/><span class="field-error" id="feedback-name-error">Enter your name.</span></label
	>
	<label class="demo-field"
		><span>Email</span
		><input
			id="feedback-email"
			type="email"
			value="invalid-address"
			aria-invalid="true"
			aria-describedby="feedback-email-error"
			autocomplete="email"
		/><span class="field-error" id="feedback-email-error"
			>Enter a valid email address.</span
		></label
	>
</div>
@use "flair";

.demo-prose {
	@extend %p-prose;
}

.demo-stack {
	@extend %p-stack;
}

.demo-danger {
	@extend %o-notice-danger;
}

.demo-field {
	@extend %o-form-field;
}

Progress and status updates

The progress element supplies its accessible value. The optional button changes only this demonstration and announces the new value politely.

40% complete

HTML and Sass 
<div class="demo-stack" data-progress-example>
	<label
		><span>Example upload</span
		><progress class="demo-progress" value="40" max="100">40%</progress></label
	>
	<p class="demo-output" role="status" data-progress-status>40% complete</p>
	<button class="demo-button" type="button" data-progress-step hidden>
		Advance example by 20%
	</button>
</div>
@use "flair";

.demo-stack {
	@extend %p-stack;
}

.demo-progress {
	@extend %o-progress;
}

.demo-button {
	@extend %o-button;
}

Using these styles

Import flair, include flair.defaults on your application root, then extend the placeholders shown in each example onto your own selectors. The demo- names belong to this website. The containing layout determines available width; theme properties are inherited.

Change the global theme to compare the same markup. Source files, dependencies, property fallbacks and behavioural requirements are documented in docs/library.md.
