Navigation

Page links, section navigation, breadcrumbs and pagination.

Primary navigation

Use ordinary links for page navigation. The current destination is identified with aria-current. On narrow screens, open the menu to reveal its links. Without JavaScript the links remain visible.

  • Navigation
  • Forms
  • Tables
  • Layouts
HTML and Sass 
<nav class="demo-navigation" aria-label="Example library navigation">
	<button type="button" aria-expanded="false" aria-controls="example-navigation-links" data-navigation-toggle hidden>Library menu</button>
	<ul id="example-navigation-links">
		<li><a href="/library/navigation/" aria-current="page">Navigation</a></li>
		<li><a href="/library/forms/">Forms</a></li>
		<li><a href="/library/tables/">Tables</a></li>
		<li><a href="/library/layouts/">Layouts</a></li>
	</ul>
</nav>
@use "flair";

.demo-navigation {
	@extend %p-navigation;
	@include flair.collapsible-navigation($from: 45rem);
}

Side navigation

This vertical pattern remains in document flow. Its parent layout supplies its width.

The same list, twice. On the left it has no indent: the label starts where the link starts. On the right a column is reserved for a glyph on every link, so labels line up whether or not a given link carries one. Only the last two do, and all four still align, because the reserved box is a minimum rather than a fixed size.

Reserving that column is a layout decision the composition makes. A theme never makes it, because a theme cannot know whether the application has glyphs to put there. --theme-side-nav-icon-size, --theme-side-nav-icon-gap and --theme-side-nav-icon-opacity size and shade it.

Using these styles

Import flair, include flair.defaults on your application root, then extend the placeholders shown in each example onto your own selectors. The demo- names belong to this website. The containing layout determines available width; theme properties are inherited.

Change the global theme to compare the same markup. Source files, dependencies, property fallbacks and behavioural requirements are documented in docs/library.md.

Search result links

A result list is ordinary navigation. Filtering this local example changes only the visible results; Flair does not implement a combobox or perform requests.

  • Forms — fields and validation
  • Layouts — responsive composition
  • Feedback — notices and progress

3 topics. Filtering is available with JavaScript.

Keep links keyboard accessible. --theme-results-max-height defaults to none; result spacing uses --theme-list-padding and --theme-result-link-padding. Empty-state wording and announcements are supplied by the application.

HTML and Sass 
<div data-search-example>
  <label class="demo-field"><span>Find a documentation topic</span><input type="search" data-result-query disabled /></label>
  <ul class="demo-search-results">
    <li><a href="/library/forms/">Forms<span class="result-detail"> — fields and validation</span></a></li>
    <li><a href="/library/layouts/">Layouts<span class="result-detail"> — responsive composition</span></a></li>
    <li><a href="/library/feedback/">Feedback<span class="result-detail"> — notices and progress</span></a></li>
  </ul>
  <p role="status" data-result-status>3 topics. Filtering is available with JavaScript.</p>
</div>
@use "flair";

.demo-search-results { @extend %p-search-results; --theme-results-max-height: 16rem; }
.demo-field { @extend %o-form-field; }

Skip links and visually hidden text

A skip link becomes visible when focused. Visually hidden text remains available to assistive technology.

Skip to the example destination

Use Tab to focus the skip link above. It appears at the top of the viewport.

Read more about accessible navigation

Example destination. Focus can move here without adding it to the normal tab order.

Give skip links real destinations and keep them early in the page order. Do not use visually hidden styling to conceal focusable controls; the skip-link object handles focus visibility separately.

Section rules and current-item markers

A sidebar that groups its links asks for the rule in markup, with data-end-of-section on the last item of a group, so the groups can change without the CSS changing.

The current link can also carry a marker in the gutter beside it. It is off until a theme gives it a width, so no layout depends on whether a theme wants one.

  • Secrets
  • New request
  • list-all-items
  • create-single-item
  • delete-single-item
    •

    Navigation patterns accept menu as well as ul, which is the more accurate element for a list of commands. Current state is read from aria-current, not from a class, so the styling and the announcement can never disagree.

    The marker is placed with --theme-side-nav-marker-width, -height, -offset, -radius and -color; the rule with --theme-side-nav-separator-space and -width.

    HTML and Sass 
    <nav class="demo-marker-navigation" aria-label="Requests">
	<menu>
		<li data-end-of-section><a href="#navigation-markers" data-icon="key">Secrets</a></li>
		<li><a href="#navigation-markers" data-icon="plus">New request</a></li>
		<li><a href="#navigation-markers" aria-current="page">list-all-items</a></li>
		<li><a href="#navigation-markers">create-single-item</a></li>
		<li><a href="#navigation-markers">delete-single-item</a></li>
	</menu>
</nav>
    @use "flair";

.demo-marker-navigation {
	@extend %p-side-navigation;
	--theme-side-nav-link-margin: 0 0 0 1rem;
	--theme-side-nav-marker-width: 4px;
	--theme-side-nav-marker-height: 1.5rem;
	--theme-side-nav-marker-offset: -0.75rem;
	--theme-side-nav-current-shadow: none;
}
