Reading layout

This layout deliberately limits text measure to 65ch. The prose pattern itself has no width limit.

Width belongs to the layout

A reading layout limits line length for continuous text. A dashboard may instead use all the available space. Neither decision should be imposed by a button, field or card.

Set --theme-prose-measure on the article layout to change its measure. Forms, grids and surfaces inside other layouts remain fluid.

	</p>

Using these styles

Import flair, include flair.defaults on your application root, then extend the placeholders shown in each example onto your own selectors. The demo- names belong to this website. The containing layout determines available width; theme properties are inherited.

Change the global theme to compare the same markup. Source files, dependencies, property fallbacks and behavioural requirements are documented in docs/library.md.

Workspace

A rail beside a field of panels. Where the sidebar layout wraps two columns intrinsically, a workspace holds any number of panels and reflows them as space allows: one panel at a narrow width, side by side when two fit.

The rail comes first in source order, so it reads first without JavaScript and the tab order matches the reading order.

  • list-all-items
  • create-single-item

    Moving a breakpoint

    A media query cannot read a CSS custom property, so Flair's layout thresholds are Sass variables. Every definition in the library reads the same four names instead of repeating a literal, which means a consuming application moves a breakpoint once and the whole library follows.

    $break-compact
    40rem. Touch targets relax to their configured height, form actions become a wrapping row, and modal dialogs become centred panels instead of sheets.
    $break-nav
    45rem. Navigation and page-tab lists lay out horizontally instead of stacking.
    $break-shell
    60rem. Two-column application shells and workspaces engage, and collapsible menus stop collapsing.
    $break-wide
    70rem. Sidebars become sticky alongside a long reading column.

    Configure them on the first @use of the library, before another module loads it. Mixins that take a $from argument default to the matching variable, so a single composition can still choose its own threshold without changing the library: flair.application-shell($from: 80rem).

    All four are overridable Sass variables in style/variable/, alongside $icon-path, $icon-extension and $icon-names. That directory is the only place the library keeps a value a consumer is expected to change in Sass; everything else is a CSS custom property, and inherited.

    HTML and Sass 
    <dl class="token-list">
	<dt><code>$break-compact</code></dt>
	<dd>40rem. Touch targets relax to their configured height, form actions become a wrapping row, and modal dialogs become centred panels instead of sheets.</dd>
	<dt><code>$break-nav</code></dt>
	<dd>45rem. Navigation and page-tab lists lay out horizontally instead of stacking.</dd>
	<dt><code>$break-shell</code></dt>
	<dd>60rem. Two-column application shells and workspaces engage, and collapsible menus stop collapsing.</dd>
	<dt><code>$break-wide</code></dt>
	<dd>70rem. Sidebars become sticky alongside a long reading column.</dd>
</dl>
