Highlight decoration

%d-highlight adds a border with four square markers outside its corners. It can frame text or a whole container. Inline text uses display: inline-block so wrapped lines share one box.

Highlighted text

This longer text wraps inside one highlighted box.

The same decoration can frame a container at its available width.

Markers use the text colour; the border inherits the theme’s border colour. Override --theme-highlight-marker-size, --theme-highlight-border-width or --theme-highlight-border-color to adjust them. The decoration uses ::before and needs space outside its border without clipping by an ancestor.

HTML and Sass 
<p><span class="demo-highlight">Highlighted text</span></p>
<div class="demo-highlight-wrap">
	<p><span class="demo-highlight">This longer text wraps inside one highlighted box.</span></p>
</div>
<div class="demo-highlight">
	<p>The same decoration can frame a container at its available width.</p>
</div>

Using these styles

Import flair, include flair.defaults on your application root, then extend the placeholders shown in each example onto your own selectors. The demo- names belong to this website. The containing layout determines available width; theme properties are inherited.

Change the global theme to compare the same markup. Source files, dependencies, property fallbacks and behavioural requirements are documented in docs/library.md.

Content with trailing actions

Rows wrap when space is limited. The text grows, while actions stay together where they fit. This works for task lists, settings and editable records.

Use .row-content for the flexible content and .row-actions for trailing controls. Optional leading content can precede both. --theme-row-gap, --theme-row-actions-gap and --theme-row-content-min configure spacing. Application code owns completion, reordering and persistence.

Panels

Where a card is a plain box, a panel divides itself: every heading is separated from the content above it by a rule, so one long editing surface stays readable without extra markup or a wrapper per section.

Request editor

Query parameters 2

Each heading closes the section above it. The panel sets no maximum width of its own.

Body

Padding, corner shape, border and shadow all come from the theme's surface.

Response viewer

An article inside a panel takes the same rhythm as a titled section, without needing a heading.

Timing

Completed in 184 ms.

The two panels here are custom elements, bound to the definition by name. Flair requires no class of its own: --theme-panel-heading-space, --theme-panel-section-space and --theme-panel-subheading-size adjust the divisions.

HTML and Sass 
<div class="demo-grid">
	<request-editor class="demo-panel">
		<h1>Request editor</h1>
		<form class="demo-form">
			<label><span>Name</span><input name="name" value="List all items" autocomplete="off" /></label>
		</form>
		<h2>Query parameters <span>2</span></h2>
		<p>Each heading closes the section above it. The panel sets no maximum width of its own.</p>
		<h2>Body</h2>
		<p>Padding, corner shape, border and shadow all come from the theme's surface.</p>
	</request-editor>
	<response-viewer class="demo-panel">
		<h1>Response viewer</h1>
		<article>
			<p>An <code>article</code> inside a panel takes the same rhythm as a titled section, without needing a heading.</p>
		</article>
		<h2>Timing</h2>
		<p>Completed in 184 ms.</p>
	</response-viewer>
</div>

Actions revealed by a row

Controls that belong to one row of a list and stay out of the way until that row is being used: a drag handle, a delete button, a reorder field.

They appear on hover and whenever focus is inside the row, so a keyboard reaches them in the same order a pointer does. They are faded, never removed from the accessibility tree, so they stay announced and tabbable throughout. Where hover is not available they are always visible, because there would be no way to reveal them.

  • list-all-items
  • create-single-item
  • delete-single-item

Point at a row, then press Tab through the list, to see both routes to the same controls. --theme-row-actions-opacity raises the resting state if the controls should always be partly visible.
