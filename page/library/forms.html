Forms

Field objects, responsive rows and action groups composed with %p-form-fields.

A form field

%o-form-field arranges a label, a native control and optional help or error text. It includes the element mapping for direct child controls, which extends the control objects documented on the Controls page . 

<label class="profile-name">
	<span>Display name</span>
	<input aria-describedby="name-help" />
	<span id="name-help" class="field-help">
		The name shown beside your comments.
	</span>
</label>

.profile-name {
	@extend %o-form-field;
}

Use a wrapping label with a span followed by its control. The label provides the association, so for and a control ID are unnecessary. Help and error messages use spans inside the label; give those messages IDs when referenced by aria-describedby . A separate .field wrapper remains available when the structure requires one.

Errors and disabled groups

Invalid state is explicit: the application sets aria-invalid="true" and provides error text. Required fields are not styled as errors before validation. A disabled fieldset uses native HTML behaviour to disable its controls together.

How the pattern is composed

  1. %o-form-field provides label, control and message layout.
  2. %o-choice-field puts a native checkbox or radio beside wrapping label text.
  3. %o-fieldset provides a bordered group with a legend, fields and choices.
  4. %p-field-row extends field objects inside a wrapping flex row. Fields wrap when their combined minimum widths and gap no longer fit the container.
  5. %p-form-actions arranges buttons without changing their DOM order. A direct .primary child extends %o-button-primary ; .action-start pushes subsequent actions towards the inline end.
  6. %p-form-fields combines these definitions into one form structure. 
@use "path/to/flair/style/flair";

:root {
	@include flair.defaults;
}

contact-form form {
	@extend %p-form-fields;
}

contact-form {
	--flair-form-gap: var(--flair-space-6);
	--flair-control-radius: .25rem;
}

Direct children of the pattern

.field or label
A wrapping label with its caption span, control and optional messages. A .field container is also supported when needed.
.field-row
A wrapping row containing direct .field or label children.
.choice
A wrapping label containing a checkbox or radio followed by its text in a span.
fieldset
A legend and direct labels, .field containers or .choice labels.
.actions
Buttons and optional application-styled links. Apply %o-button to a link selector if it should look like a button.

These hooks describe structural roles. They are not a list of visual utility classes. Existing applications can extend the smaller objects and patterns on their own selectors when their markup differs. Arbitrary wrapper depths and nested components are intentionally not traversed.

Form properties

--flair-form-gap
Space between fields and within rows and groups. Falls back to --flair-space-4 (1rem).
--flair-field-gap
Space between a label, control and message. Falls back to --flair-space-2 (0.5rem).
--flair-field-min-width
Preferred field width before a row wraps. Default: 14rem. Fields can shrink below this to fit narrow containers.
--flair-label-weight
Label, legend and error-text weight. Default: 500.
--flair-fieldset-padding
Falls back to --flair-space-4 .
--flair-actions-align , --flair-actions-gap , --flair-actions-margin
Action justification, gap and block-start margin. Defaults: flex-end, spacing step 3, spacing step 2.

Output and responsibility

Only extended placeholders produce rules. Including defaults() explicitly emits variables; including controls() explicitly emits native element selectors. Extending a form also includes the objects it depends on. Sass does not inspect the HTML to remove unused parts of that pattern.

Extensions add selectors where the original placeholder is defined, not where the extension is written. Use CSS properties for theme changes and local declarations for application-specific adjustments. Extending a placeholder from inside an unrelated media query is not supported; apply responsive property overrides instead.

The library adds no JavaScript, validation logic, network requests or submission handlers. The global theme selector, example spacing controls and submission acknowledgement belong to this website. Themes change CSS properties; native browser controls may still render differently between browsers.
