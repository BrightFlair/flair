Forms

Field objects, responsive rows and action groups composed with %p-form-fields.

A form field

%o-form-field arranges a label, a native control and optional help or error text. It includes the element mapping for direct child controls, which extends the control objects documented on the Controls page . 

<label class="profile-name">
	<span>Display name</span>
	<input aria-describedby="name-help" />
	<span id="name-help" class="field-help">
		The name shown beside your comments.
	</span>
</label>

.profile-name {
	@extend %o-form-field;
}

Use a wrapping label with a span followed by its control. The label provides the association, so for and a control ID are unnecessary. Help and error messages use spans inside the label; give those messages IDs when referenced by aria-describedby . A separate .field wrapper remains available when the structure requires one.

Wrapping labels

The checkbox stays alongside the first line. Subsequent lines start beneath the label text.

Larger text and line spacing

Alignment follows the label's line height, including when a theme changes its font. Use the theme selector to compare appearances.

.notification-choice {
	@extend %o-choice-field;
	--theme-font-size: 1.5rem;
	--theme-line-height: 1.8;
}

Errors and disabled groups

Invalid state is explicit: the application sets aria-invalid="true" and provides error text. Required fields are not styled as errors before validation. A disabled fieldset uses native HTML behaviour to disable its controls together.

Unavailable settings

Form in a narrow layout

The containing surface controls available width. The same form pattern wraps its field row without applying a maximum width to the form itself.

Compound fields

Two or more controls that read as a single value: a method beside a URL, a currency beside an amount, a date range. They stack while space is short and form one row when it is not.

Each control keeps its own label, so the pairing is presentational and every control keeps its own accessible name. data-span="narrow" holds one to its content width instead of letting it grow.

Narrow the window to watch each pair stack in source order. --theme-compound-narrow sets the fixed measure, and --theme-compound-gap the space between controls. Applications whose controls must remain joined can set --theme-compound-direction: row, then assign their mobile shares with --theme-compound-field-flex and --theme-compound-narrow-flex. The compact layout remains independently configurable through --theme-compound-compact-direction and --theme-compound-compact-align-items.

HTML and Sass 
<form class="demo-form">
	<div class="demo-compound-field">
		<label data-span="narrow">
			<span>Method</span>
			<select name="method">
				<option>GET</option>
				<option>POST</option>
				<option>PUT</option>
				<option>DELETE</option>
			</select>
		</label>
		<label>
			<span>Endpoint</span>
			<input type="url" name="endpoint" placeholder="https://api.example.com/items" />
		</label>
	</div>
	<div class="demo-compound-field">
		<label><span>Valid from</span><input type="date" name="from" /></label>
		<label><span>Valid until</span><input type="date" name="until" /></label>
	</div>
</form>

Repeatable field groups

A list of identical field groups that an application adds to and removes from: query parameters, headers, endpoints. Only the first row draws its labels, so the list reads as a table without becoming one.

The labels stay in the markup on every row and are positioned out of view rather than removed, so each control is still named for assistive technology. An empty list explains itself from data-term.

    The second list is empty, and states what is missing from its own data-term rather than from a message held in the CSS. Adding and removing rows, and the order they appear in, belong to the application. --theme-repeat-field-wrap: nowrap keeps every row's fields and actions together when the controls can shrink to fit; --theme-repeat-row-wrap independently controls wrapping around the row form.

    HTML and Sass 
    <ul class="demo-repeatable-fields" data-term="headers">
	<li>
		<form>
			<label><span>Key</span><input name="key" value="Accept" autocomplete="off" /></label>
			<label><span>Value</span><input name="value" value="application/json" autocomplete="off" /></label>
			<div class="actions">
				<button class="demo-button" type="button">Save</button>
				<button class="demo-icon-button" type="button" data-icon="trash"><span>Delete</span></button>
			</div>
		</form>
	</li>
	<li>
		<form>
			<label><span>Key</span><input name="key" value="Authorization" autocomplete="off" /></label>

    Input groups

    Join several native controls into the space of one field. Touching controls have square inner corners and one shared border; only the outside corners retain the theme's rounding. Every editable control keeps its own label, focus and keyboard behaviour.

    Email sender
    Edit the prefix; @login.example.com is fixed and disabled.
    Website address
    A disabled prefix makes the required scheme visible.
    Full name
    Both fields are editable and keep their own accessible names.
    Repository path
    A disabled field can sit between two editable fields.
    Amount and currency
    A native select and number field share the same frame.

    Use data-span="narrow" for a content-sized prefix, suffix or select. Other fields share the remaining width. The HTML size attribute supplies a fallback measure for fixed text where content sizing is unavailable.

    Disabled controls are visible context, not submitted values, and are skipped by Tab. The application must supply and enforce fixed portions when saving. Use readonly instead when a text value should stay focusable and be submitted.

    How the pattern is composed

    1. %o-form-field provides label, control and message layout.
    2. %o-choice-field puts a native checkbox or radio beside wrapping label text.
    3. %o-fieldset provides a bordered group with a legend, fields and choices.
    4. %p-field-row extends field objects inside a wrapping flex row. Fields wrap when their combined minimum widths and gap no longer fit the container.
    5. %p-form-actions arranges buttons without changing their DOM order. A direct .primary child extends %o-button-primary ; .action-start pushes subsequent actions towards the inline end.
    6. %p-form-fields combines these definitions into one form structure. 
    @use "path/to/flair/style/lib/flair";

:root {
	@include flair.defaults;
}

contact-form form {
	@extend %p-form-fields;
}

contact-form {
	--theme-form-gap: var(--theme-space-6);
	--theme-control-radius: .25rem;
}

    Direct children of the pattern

    .field or label
    A wrapping label with its caption span, control and optional messages. A .field container is also supported when needed.
    .field-row
    A wrapping row containing direct .field or label children.
    .choice
    A wrapping label containing a checkbox or radio followed by its text in a span.
    fieldset
    A legend and direct labels, .field containers or .choice labels.
    .actions
    Buttons and optional application-styled links. Apply %o-button to a link selector if it should look like a button.

    These hooks describe structural roles. They are not a list of visual utility classes. Existing applications can extend the smaller objects and patterns on their own selectors when their markup differs. Arbitrary wrapper depths and nested components are intentionally not traversed.

    Form properties

    --theme-form-gap
    Space between fields and within rows and groups. Falls back to --theme-space-4 (1rem).
    --theme-field-gap
    Space between a label, control and message. Falls back to --theme-space-2 (0.5rem).
    --theme-field-min-width
    Preferred field width before a row wraps. Default: 14rem. Fields can shrink below this to fit narrow containers.
    --theme-label-weight
    Label, legend and error-text weight. Default: 500.
    --theme-fieldset-padding
    Falls back to --theme-space-4 .
    --theme-actions-align , --theme-actions-gap , --theme-actions-margin
    Action justification, gap and block-start margin. Defaults: flex-end, spacing step 3, spacing step 2.
    --theme-actions-direction , --theme-actions-wrap and --theme-action-white-space
    The narrow-layout direction, wrapping and button text wrapping. Set these when a compact toolbar must remain one horizontal row. The compact breakpoint can be configured separately with --theme-actions-compact-direction and --theme-actions-compact-align-items.

    Output and responsibility

    Only extended placeholders produce rules. Including defaults() explicitly emits variables; including controls() explicitly emits native element selectors. Extending a form also includes the objects it depends on. Sass does not inspect the HTML to remove unused parts of that pattern.

    Extensions add selectors where the original placeholder is defined, not where the extension is written. Use CSS properties for theme changes and local declarations for application-specific adjustments. Extending a placeholder from inside an unrelated media query is not supported; apply responsive property overrides instead.

    The library adds no JavaScript, validation logic, network requests or submission handlers. The global theme selector, example spacing controls and submission acknowledgement belong to this website. Themes change CSS properties; native browser controls may still render differently between browsers.
