Using these styles

Import flair, include flair.defaults on your application root, then extend the placeholders shown in each example onto your own selectors. The demo- names belong to this website. The containing layout determines available width; theme properties are inherited.

Change the global theme to compare the same markup. Source files, dependencies, property fallbacks and behavioural requirements are documented in docs/library.md.

An explicit document baseline

Applications can opt into box sizing, a margin reset on body, and preservation of the native hidden attribute. The library remains silent on import.

Structured data as a tree

A serialised document drawn as a tree the reader can collapse: a JSON response, an XML body, a configuration file. Every node is a native details, so the whole structure expands, collapses, prints and is reachable by keyboard with no script at all.

A closed node draws on one line, summarising what it holds; an open one indents its branch. Token colours come from the syntax decoration, so they follow the theme along with everything else.

{
status: "ok",
items: [
{ … }
id: 4210, name: "Bridle", archived: false
{ … }
id: 4211, name: "Saddle", notes: null
]
}

Open and close the nodes, and try it with the keyboard. Parsing the document, deciding what counts as a leaf and choosing which nodes start open are the application's work; the pattern only arranges what it is given.

The format is named once, by the container's data-language. --theme-syntax-tree-indent, -guide-width, -guide-color and -guide-space control the indentation and its guide line.

HTTP response metadata

Status, response identifier and time form a compact summary for an HTTP exchange. The badges and muted timestamp inherit their colours from the active theme, and the summary keeps native disclosure behaviour when used inside details.

200 OK RES_01J8X4H2M6 12:04:31

The response content belongs here.

--theme-http-status-background, --theme-http-id-background, and --theme-http-metadata-gap adapt the row without changing its structure.

HTML and Sass 
<details open>
	<summary class="response-metadata">
		<span class="status">200 OK</span>
		<span class="id">RES_01J8X4H2M6</span>
		<time datetime="2026-09-19T12:04:31Z">12:04:31</time>
	</summary>
	<p>The response content belongs here.</p>
</details>

Labelled output regions

A bordered block of output with its own caption resting above the top edge: a response body, a log excerpt, a diff. The caption is generated from data-label, so the element holds nothing but the output and can be replaced wholesale without disturbing the frame.

{ "status": "ok", "items": 2 }

The second region is empty. Rather than drawing a box around nothing, it drops its border and says what is missing, using the same empty-message decoration as a list.

HTML and Sass 
<div class="demo-stack">
	<div class="demo-labelled-region" data-label="Body">{
	"status": "ok",
	"items": 2
}</div>
	<div class="demo-labelled-region" data-label="Body" data-term="response bodies"></div>
</div>
