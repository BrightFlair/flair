Controls

Native inputs, buttons and the Sass definitions used to style them.

Definitions and dependencies

The entry point style/flair.scss loads definitions without emitting any CSS. Include the default variables once, then extend the objects you need. Fonts are supplied by the application; these examples use the Ubuntu files installed on this website.

  1. mixin/defaults.scss provides defaults() : monochrome colours, spacing, typography and control sizes.
  2. %d-focus-ring defines the keyboard focus outline.
  3. %d-control defines padding, border, background, text and native disabled state. Its focus-visible rule extends %d-focus-ring .
  4. %o-control extends %d-control for text inputs, selects and textareas. It adds full width, placeholder text and read-only presentation.
  5. %o-button extends %d-control for buttons and links. %o-button-primary extends it for the primary action.
  6. %o-choice and %o-range retain native checkbox, radio and range appearance and extend the focus ring. %o-color extends the control decoration with a smaller swatch size. 
@use "path/to/flair/style/flair";

:root {
	@include flair.defaults;
}
.search-input {
	@extend %o-control;
}
.download-link {
	@extend %o-button;
}
.save-button {
	@extend %o-button-primary;
}

Alternatively, include flair.controls() to apply objects to native tags. At the stylesheet root this emits global element defaults; inside a selector it limits them to that region. Hidden and image inputs are excluded. Checkboxes, radios, range and colour inputs receive their own objects. 

.search-area {
	@include flair.controls;
}

Control states

Use the global theme selector to change the page and its examples. Focus a control using the keyboard to inspect its outline. Invalid and read-only examples have dashed and dotted borders respectively. Error text identifies the problem independently of colour.

Buttons and choices

These buttons have no application action. A link styled as a button still navigates. Use native disabled on buttons; styling alone cannot disable a link or prevent an action.

CSS properties

Set properties on the application root or on a containing element. Objects read these values without assigning local defaults that would override inherited settings. The default mixin should be included once per independent theme scope.

--theme-color-*
Text, muted text, surface, disabled surface, border, accent, on-accent and danger colours.
--theme-font-body , --theme-font-size , --theme-font-weight , --theme-line-height
Shared control and field typography. Default: Ubuntu, 1rem, 400, 1.5.
--theme-control-padding-block , --theme-control-padding-inline
Fallback: spacing steps 2 and 3 (0.5rem and 0.75rem).
--theme-control-min-height , --theme-control-radius
Default minimum height: 2.75rem. Radius falls back to the shared radius, initially zero.
--theme-control-background , --theme-control-text , --theme-control-border
Control-specific overrides of the semantic colours.
--theme-focus-color , --theme-focus-width , --theme-focus-offset
Default: accent colour, 3px width, 2px offset.
--theme-button-*
Button background, text and weight, hover background, and primary-action colours. See the complete reference below.

The complete property list, markup contract and extension examples are in the form documentation and docs/forms.md in the repository.

Icons

A glyph is asked for in markup, by name: data-icon="trash" names the file, and data-icon-end puts one after the content instead. Flair turns the registered names into URLs at compile time, because CSS cannot build a URL from an attribute value.

The glyph is a mask filled with currentColor, so it takes the colour of the text beside it and needs no separate rule in a dark scheme. Set the directory and file extension once with $icon-path and $icon-extension.

Read the code section Secrets are hidden

Registering the set is one line, and an unregistered name emits no rule at all, so an icon directory never becomes dead CSS. --theme-icon-size, --theme-icon-gap and --theme-icon-opacity adjust a glyph without touching the file it comes from.

HTML and Sass 
<div class="demo-icons">
	<button class="demo-button" type="button" data-icon="trash">Delete</button>
	<button class="demo-button" type="button" data-icon="copy">Copy</button>
	<button class="demo-primary" type="button" data-icon="plus">New request</button>
	<a class="demo-link" href="/library/code/" data-icon-end="link-external">Read the code section</a>
	<span data-icon="lock">Secrets are hidden</span>
</div>
@use "flair" with (
	$icon-path: "/asset/icon/",
	$icon-names: (trash, copy, plus, lock, link-external)
);

.demo-icons {
	@include flair.icon;
	display: flex;
	flex-wrap: wrap;
	align-items: center;
	gap: var(--theme-space-3);
}

Icon-only buttons

A button whose meaning is carried by its glyph still needs its wording. The label stays in the document at all times and is revealed on hover and on keyboard focus, so the button is announced properly and is never a control with no accessible name.

Focus each button with Tab to see the same label a pointer reveals. The last three are a light, dark and system control; which of them is current, and what happens when one is pressed, is the application's decision.

HTML and Sass 
<div class="demo-icons">
	<button class="demo-icon-button" type="button" data-icon="trash"><span>Delete</span></button>
	<button class="demo-icon-button" type="button" data-icon="copy"><span>Copy to clipboard</span></button>
	<button class="demo-icon-button" type="button" data-icon="share"><span>Share</span></button>
	<button class="demo-icon-button" type="button" data-icon="device-desktop"><span>Match the system</span></button>
	<button class="demo-icon-button" type="button" data-icon="sun"><span>Always light</span></button>
	<button class="demo-icon-button" type="button" data-icon="moon"><span>Always dark</span></button>
</div>
@use "flair";

.demo-icon-button {
	@extend %o-icon-button;
}
